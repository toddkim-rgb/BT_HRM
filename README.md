# BT-HRM · SM·SI 사업부문 인력관리 시스템

[SM_SI_인력관리시스템_명세서.md](SM_SI_인력관리시스템_명세서.md)(v1.0)를 기준으로 개발하는 인력관리 시스템입니다.

| 구분 | 기술 |
|---|---|
| 프론트엔드 | React 19 + TypeScript + Vite, 모바일 반응형 |
| 백엔드 | Node.js + Express 5 + TypeScript |
| DB | Prisma ORM + SQLite (개발). 운영 시 PostgreSQL 등으로 전환 |
| 인증 | 이메일 + 비밀번호, JWT |

## 실행 방법

필요 환경: Node.js 20.6 이상 (개발 환경은 Node 24)

```bash
npm run setup   # .env 생성 + 의존성 설치 + DB 생성 + 초기 데이터
npm run dev     # API(4000) + 웹(5173) 동시 실행
```

브라우저에서 **http://localhost:5173** 에 접속합니다. (개발 중 http://localhost:4000 으로 들어오면 5173으로 자동 이동합니다.)

운영 배포는 `npm run build` 후 `npm start`로 실행하며, API 서버(4000)가 빌드된 화면도 함께 제공합니다.

### 운영 DB 전환 (PostgreSQL 예)

1. `server/prisma/schema.prisma`에서 `provider = "postgresql"`로 바꿉니다.
2. `server/.env`의 `DATABASE_URL`을 운영 DB 주소로 바꿉니다.
3. `server/prisma/migrations` 폴더를 지우고 `npx prisma migrate dev --name init`으로 마이그레이션을 다시 만듭니다.

## 개발 범위 (명세 v1.0)

세 가지 핵심 목표에 집중합니다: **프로젝트별 투입인력 · 인력별 가동률 · 주간보고 자동화**

| 구분 | 범위 | 상태 |
|---|---|---|
| 기반 | 이메일 로그인·권한, 로그인 보조(비밀번호 재설정 요청·ID 찾기), 인력(삭제·복구)·협력사·프로젝트 기준정보, 기준값·공휴일 | ✅ 완료 |
| 투입 | 투입 배정(다중 프로젝트 투입·과투입 %), 프로젝트 MM | ✅ 완료 |
| 주간보고 자동화 | 개인 주간 업무보고(전주 계획 이월·배정대로 채우기·제출 검증) → 프로젝트 주간보고(자동 취합·주요 마일스톤·PM 의견·확정) → 전사 One-Page(자동 집계·확정·인쇄/PDF) | ✅ 완료 |
| 프로젝트별 투입인력 | 프로젝트별 투입현황(프로젝트 카드 → 상세, 인력별, 6개월 타임라인), 다중 투입·과투입·대기 표시 | ✅ 완료 |
| 인력별 가동률 | 월 가동률(총/유상), 주의 인력(대기·저가동·과투입·투입 공백), 다음 달 예상 가동률, 6개월 추이 | ✅ 완료 |
| 차기 검토 | 단가·손익, 협력사 인력 계약, 수급 계획, 알림 | 보류 |

## 구현 시 정한 사항

명세에 없거나 해석이 필요했던 부분입니다. 바꿔야 하면 알려 주세요.

- **주간보고 확정:** 승인 절차 없이 제출하면 바로 확정되어 집계에 반영됩니다. 제출 후에도 고쳐서 다시 제출('수정 제출')할 수 있고, 검증에 걸리면 기존 제출 내용이 그대로 유지됩니다.
- **제출 검증:** 지연 사유 누락과 SI 진척률 미입력은 제출할 수 없습니다. 투입 MD 합계가 영업일과 다르거나 차주 계획이 없으면 경고만 하고, 확인 후 제출할 수 있습니다.
- **주간보고 자동화:** 프로젝트 주간보고와 전사 One-Page는 따로 생성하지 않고, 화면을 열 때마다 제출된 주간 업무보고로 다시 집계합니다. '확정'하면 그 시점 내용으로 고정됩니다. PDF는 One-Page 화면의 '인쇄 / PDF 저장'(A4 가로)을 씁니다.
- **프로젝트 진척률:** PM이 주요 마일스톤(이름·계획일)을 등록하고 완료 체크합니다. 진척률 = 완료 수 ÷ 전체 수, 계획일이 지난 미완료 마일스톤은 '지연'으로 표시됩니다.
- **인력 삭제:** 배정·주간보고 등 이력이 있으면 '삭제 처리(보관)'되어 목록·로그인에서 빠지고 과거 집계는 유지됩니다. 인력 화면 '삭제된 인력' 탭에서 복구할 수 있습니다. 이력이 없으면 완전히 삭제됩니다.
- **사번 없음:** 인력은 이메일로 식별합니다. DB 내부 키(`empId`)는 자동 부여되며 화면에 표시하지 않습니다. ID 찾기는 성명 + 연락처로 확인합니다(데모 홍길동: 010-3000-3001).
- **비밀번호 재설정:** 메일을 보내지 않고, 로그인 화면의 요청을 시스템관리자가 '계정 요청' 메뉴에서 처리해 임시 비밀번호를 발급합니다. 초기·임시 비밀번호로 로그인하면 새 비밀번호(8자 이상, 영문·숫자)를 설정해야 다른 화면을 쓸 수 있습니다. 데모 계정은 변경 강제 없이 바로 로그인됩니다.
- **다중 프로젝트 투입:** 명세서 5.5를 참고하세요. 같은 프로젝트에 기간이 겹치는 중복 배정도 허용합니다.
- **투입 대상 여부:** 인력 마스터에 `투입 대상` 항목을 추가했습니다. 관리·영업·경영진처럼 해제된 인력은 가동률·대기 인원 집계에서 빠집니다.
- **진행 중인 달의 가동률:** 가용 MD를 월 전체가 아니라 오늘까지의 영업일로 계산합니다. 지난 달은 월 전체 영업일 기준입니다.
- **배정 상태:** 투입예정·투입중·종료는 날짜로 자동 계산하고, 취소만 따로 저장합니다.
- **인력 일괄 등록:** 엑셀 양식을 CSV(UTF-8)로 저장해 올리는 방식입니다.
